### MindVault — Complete Android Application Blueprint

We're going to design MindVault as a native Android application with a clear architecture, a polished interface, local data storage, and room for future C++ native processing.

The application will have these principles:

* 100% offline: No account, server, or internet connection required.

* Local-first: All user data stays on the device.

* Adaptive design: Light and dark themes, following Android system settings, with manual override.

* Native Android: Java, XML layouts, Android SDK, Material Design 3.

* Native engine: C++ NDK for future high-performance processing.

* Expandable architecture: New features should not require rewriting the original application.

### Architecture responsibilities

| Layer      | Responsibility             |
| ---------- | -------------------------- |
| Activities | Host the application       |
| Fragments  | Display screens            |
| ViewModels | Manage UI state            |
| Repository | Coordinate data operations |

### 6\. Database design

The database is the foundation of MindVault.

I recommend SQLite through Android Room.

Database name:

`mindvault.db`

Version:

`1`

### Database entities

### 1\. Notes table

| Column      | Type    | Description            |
| ----------- | ------- | ---------------------- |
| id          | INTEGER | Primary key            |
| title       | TEXT    | Note title             |
| content     | TEXT    | Note body              |
| category_id | INTEGER | Associated category    |
| is_pinned   | INTEGER | Pin status             |
| is_archived | INTEGER | Archive status         |
| is_deleted  | INTEGER | Soft-delete status     |
| created_at  | INTEGER | Creation timestamp     |
| updated_at  | INTEGER | Modification timestamp |

### 2\. Categories table

| Column     | Type    | Description        |
| ---------- | ------- | ------------------ |
| id         | INTEGER | Primary key        |
| name       | TEXT    | Category name      |
| color      | TEXT    | Category color     |
| icon       | TEXT    | Icon identifier    |
| created_at | INTEGER | Creation timestamp |

Initial categories:

* Personal

* Ideas

* Work

* Programming

* Learning

* Projects

* Uncategorized

### 3\. Tags table

| Column     | Type    | Description        |
| ---------- | ------- | ------------------ |
| id         | INTEGER | Primary key        |
| name       | TEXT    | Tag name           |
| created_at | INTEGER | Creation timestamp |

### 4\. NoteTags table

This is a many-to-many relationship.

A single note can have multiple tags, and a single tag can belong to multiple notes.

| Column  | Type    |
| ------- | ------- |
| note_id | INTEGER |
| tag_id  | INTEGER |

Composite primary key: `(note_id, tag_id)`.

### 5\. NoteFTS table

An SQLite full-text search index.

| Column  | Type |
| ------- | ---- |
| title   | TEXT |
| content | TEXT |

This table indexes note content for efficient local searching.

### Database relationship diagram

```mermaid

erDiagram
    CATEGORIES ||--o{ NOTES : contains
    NOTES ||--o{ NOTE_TAGS : has
    TAGS ||--o{ NOTE_TAGS : assigned
    NOTES ||--|| NOTE_FTS : indexed

    CATEGORIES {
        integer id PK
        text name
        text color
        text icon
    }

    NOTES {
        integer id PK
        text title
        text content
        integer category_id FK
        integer is_pinned
        integer is_archived
        integer is_deleted
        integer created_at
        integer updated_at
    }

    TAGS {
        integer id PK
        text name
        integer created_at
    }

    NOTE_TAGS {
        integer note_id PK,FK
        integer tag_id PK,FK
    }

    NOTE_FTS {
        text title
        text content
    }
```

### Database rules

* Deleting a note should cascade-delete its tag relationships.

* Deleting a category should set associated notes to Uncategorized.

* Deleting a tag should remove its note relationships.

* Normal deletion should initially use a soft-delete flag.

* Search must exclude archived and deleted notes by default.

* Timestamps should use Unix milliseconds.

* All writes must execute away from the main thread.

### Theme switching in Java

Use AppCompat's night mode support:

```java
public void applyTheme(String mode) {

    switch (mode) {

        case "light":
            AppCompatDelegate.setDefaultNightMode(
                AppCompatDelegate.MODE_NIGHT_NO
            );
            break;

        case "dark":
            AppCompatDelegate.setDefaultNightMode(
                AppCompatDelegate.MODE_NIGHT_YES
            );
            break;

        default:
            AppCompatDelegate.setDefaultNightMode(
                AppCompatDelegate.MODE_NIGHT_FOLLOW_SYSTEM
            );
    }
}
```

Persist the selected value using SharedPreferences.

### Step 4 — Create NoteDao

File: `data/database/NoteDao.java`

```java
package com.mindvault.app.data.database;

import androidx.lifecycle.LiveData;
import androidx.room.Dao;
import androidx.room.Insert;
import androidx.room.Update;
import androidx.room.Delete;
import androidx.room.Query;

import com.mindvault.app.data.database.entities.NoteEntity;

import java.util.List;

@Dao
public interface NoteDao {

    @Insert
    long insert(NoteEntity note);

    @Update
    void update(NoteEntity note);

    @Query("""
        SELECT * FROM notes
        WHERE is_deleted = 0
        AND is_archived = 0
        ORDER BY is_pinned DESC, updated_at DESC
    """)
    LiveData<List<NoteEntity>> getAllNotes();

    @Query("""
        SELECT * FROM notes
        WHERE id = :id
        LIMIT 1
    """)
    LiveData<NoteEntity> getNote(long id);

    @Query("""
        SELECT COUNT(*) FROM notes
        WHERE is_deleted = 0
        AND is_archived = 0
    """)
    LiveData<Integer> getNoteCount();

    @Query("""
        SELECT * FROM notes
        WHERE is_deleted = 0
        AND is_archived = 0
        AND id IN (
            SELECT rowid FROM note_fts
            WHERE note_fts MATCH :query
        )
        ORDER BY updated_at DESC
    """)
    LiveData<List<NoteEntity>> searchNotes(String query);

    @Query("""
        UPDATE notes
        SET is_deleted = 1,
            updated_at = :time
        WHERE id = :id
    """)
    void softDelete(long id, long time);

    @Query("""
        UPDATE notes
        SET is_pinned = :pinned,
            updated_at = :time
        WHERE id = :id
    """)
    void setPinned(long id, boolean pinned, long time);
}
```

For FTS search, sanitize user input and construct valid FTS expressions. Don't pass arbitrary raw query syntax without handling quotes and operators.

### Step 5 — Create MindVaultDatabase

File: `data/database/MindVaultDatabase.java`

```java
package com.mindvault.app.data.database;

import android.content.Context;

import androidx.room.Database;
import androidx.room.Room;
import androidx.room.RoomDatabase;

import com.mindvault.app.data.database.entities.*;

@Database(
    entities = {
        NoteEntity.class,
        CategoryEntity.class,
        TagEntity.class,
        NoteTagEntity.class,
        NoteFtsEntity.class
    },
    version = 1,
    exportSchema = true
)
public abstract class MindVaultDatabase
        extends RoomDatabase {

    private static volatile MindVaultDatabase INSTANCE;

    public abstract NoteDao noteDao();

    public static MindVaultDatabase getInstance(
            Context context) {

        if (INSTANCE == null) {

            synchronized (MindVaultDatabase.class) {

                if (INSTANCE == null) {

                    INSTANCE = Room.databaseBuilder(
                        context.getApplicationContext(),
                        MindVaultDatabase.class,
                        "mindvault.db"
                    )
                    .build();
                }
            }
        }

        return INSTANCE;
    }
}
```

Also create `CategoryDao` and `TagDao` for their CRUD operations before implementing their screens.

Database safety: Keep Room schema export enabled and commit exported schema JSON files to version control. Do not use destructive migrations when users already have valuable notes.

### Step 6 — Create NoteRepository

The Repository separates database operations from the UI.

File: `data/repository/NoteRepository.java`

```java
package com.mindvault.app.data.repository;

import android.content.Context;

import androidx.lifecycle.LiveData;

import com.mindvault.app.data.database.MindVaultDatabase;
import com.mindvault.app.data.database.NoteDao;
import com.mindvault.app.data.database.entities.NoteEntity;

import java.util.List;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class NoteRepository {

    private final NoteDao noteDao;

    private final ExecutorService executor =
        Executors.newFixedThreadPool(2);

    public NoteRepository(Context context) {

        MindVaultDatabase db =
            MindVaultDatabase.getInstance(context);

        noteDao = db.noteDao();
    }

    public LiveData<List<NoteEntity>> getAllNotes() {
        return noteDao.getAllNotes();
    }

    public LiveData<Integer> getNoteCount() {
        return noteDao.getNoteCount();
    }

    public void insert(NoteEntity note) {
        executor.execute(() -> noteDao.insert(note));
    }

    public void update(NoteEntity note) {
        executor.execute(() -> {

            note.updatedAt = System.currentTimeMillis();

            noteDao.update(note);
        });
    }

    public void delete(long id) {
        executor.execute(() ->
            noteDao.softDelete(
                id,
                System.currentTimeMillis()
            )
        );
    }

    public void setPinned(long id, boolean pinned) {
        executor.execute(() ->
            noteDao.setPinned(
                id,
                pinned,
                System.currentTimeMillis()
            )
        );
    }
}
```

For production, expose a repository search method, add lifecycle-aware executor cleanup, and return operation results so the editor can distinguish successful saves from failures.

### Step 7 — Connect the C++ NDK engine

The native engine is deliberately small in Phase 1.

We establish the JNI bridge now so that future graph algorithms, indexing, and native processing can be integrated without restructuring the application.

File: `nativeengine/NativeBridge.java`

```java
package com.mindvault.app.nativeengine;

public class NativeBridge {

    static {
        System.loadLibrary("mindvault");
    }

    public native String getEngineVersion();

    public native int calculateTextLength(String text);
}
```

File: `cpp/native-lib.cpp`

```cpp
#include <jni.h>
#include <string>

extern "C"
JNIEXPORT jstring JNICALL
Java_com_mindvault_app_nativeengine_NativeBridge_getEngineVersion(
        JNIEnv* env,
        jobject /* this */) {

    std::string version = "MindVault Native Engine 1.0";

    return env->NewStringUTF(version.c_str());
}

extern "C"
JNIEXPORT jint JNICALL
Java_com_mindvault_app_nativeengine_NativeBridge_calculateTextLength(
        JNIEnv* env,
        jobject /* this */,
        jstring text) {

    if (text == nullptr) {
        return 0;
    }

    const char* chars = env->GetStringUTFChars(
        text, nullptr
    );

    if (chars == nullptr) {
        return 0;
    }

    int length = 0;

    for (const char* p = chars; *p; ++p) {
        ++length;
    }

    env->ReleaseStringUTFChars(text, chars);

    return length;
}
```

Note that this sample calculates modified UTF-8 byte length, not Unicode character count. The method is just a JNI integration test, not the final text-processing implementation.

`cpp/CMakeLists.txt`

```cmake

    SHARED

)

    log
)

)
```
